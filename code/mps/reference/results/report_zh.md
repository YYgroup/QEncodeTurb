# Velocity-field MPS compression experiment

Only the three exported real velocity components are analyzed, without complex spinor-state analysis or time evolution. The spatial registers contain 15, 18, 21, 24, and 27 qubits. Each uses one realization with seeds 2025 and 2026.

## Settings and code sources

Velocity fields were generated by the existing project without modification. Settings are k_cutoff=15, locality_radius=3, sparse probability-tail tolerance 1e-12, and the FDM velocity definition; component_ratio is 0.5, 0.5, 0.08, 0.02, and 0.006, respectively. Source and output SHA-256 hashes appear in fields/n*/complete.json. After export, the MPS analysis no longer imports geoencode_turb.

The original source is [Gourianov et al., Nat. Comput. Sci. 2, 30–37 (2022)](https://doi.org/10.1038/s43588-021-00181-1), with a [code archive](https://doi.org/10.25592/uhhfdm.14234). original/ preserves the extracted MATLAB/C sources, and original_provenance.json records their checksums. The original README states that the C evolution solver depends on the non-open-source TNT library. This experiment uses the public MATLAB velocity-field MPS construction and analysis workflow, without running that C evolution solver.

The unmodified createMPS3D.m, createMPSandAnalyse3D.m, reconstructFromNik3D.m, and memComp.m routines were executed in portable GNU Octave 11.3.0 for a 32^3 velocity component. Large-grid calculations use a Python numerical adapter: tensor-axis permutations replace pointwise binary counting, dense LAPACK SVD replaces svds, and global error control is added. Adapter runtimes are not reported as original MATLAB runtimes.

The original three-dimensional octal scale encoding is retained. Each site represents one scale, with physical dimension d=8, L=n/3 sites, and local index omega=x_bit+2*y_bit+4*z_bit, ordered from coarse to fine. Here chi denotes the dimension between adjacent scale groups, not the maximum binary-MPS dimension obtained by separating the three bits within each group.

## Error and bond-dimension definitions

Each component independently satisfies $\|u_i-\widetilde u_i\|_2/\|u_i\|_2\leq\epsilon$. Schmidt spectra are computed independently from every cut of the original velocity tensor, not estimated from a truncated MPS. Entropy is $S_\ell=-\sum_\alpha p_{\ell,\alpha}\log_2p_{\ell,\alpha}$, where $p_{\ell,\alpha}=\sigma_{\ell,\alpha}^2/\|u_i\|_2^2$.

The single-cut truncation condition is $\sum_{\alpha>r}\sigma_{\ell,\alpha}^2\leq\epsilon^2\|u_i\|_2^2$. Maximizing the necessary ranks over cuts gives a lower bound on chi for any MPS satisfying the component error. The constructed uniform cap is the smallest integer for which the sum of all cut-tail energies lies within the squared-error budget; fixed-cap TT-SVD then follows the original order. This condition is sufficient but generally not necessary, so the tables distinguish lower bounds from constructed ranks. Every final MPS is fully contracted, its original-grid relative L2 error is checked directly, and the result is compared with the certificate from sequentially discarded singular values.

Complete spectra use LAPACK SVD for smaller cuts and all eigenvalues of the smaller Gram matrix when the minimum matrix dimension exceeds 1024. Negative roundoff eigenvalues are clipped to zero. Spectrum squared-norm residuals and MATLAB cross-checks appear in validation.json. The strictest relative L2 tolerance is 1e-4; spectral tails far below numerical precision are not physically interpreted.

Actual core storage is $P_{\mathrm{store}}=\sum_{\ell=1}^L8r_{\ell-1}r_\ell$ real scalars, with boundary ranks 1. Following the original memComp.m, the gauge-reduced count is $P_{\mathrm{NVPS}}=P_{\mathrm{store}}-\sum_{\ell=1}^{L-1}r_\ell^2$. Gauge-reduced parameter count and stored core bytes are distinct quantities and are reported separately. The dense three-component representation contains $3N^3$ float64 real scalars.

summary.csv also gives a necessary storage lower bound by substituting each necessary cut rank into the core-storage formula. This bound does not depend on the sufficient truncation budget used for construction. If it exceeds dense storage, any MPS satisfying the componentwise error with the same octal encoding and explicitly stored dense cores lacks a core-array storage advantage. This does not exclude alternative orderings, sparse cores, other tensor networks, or other classical compression schemes.

The uniform-cap construction does not minimize parameter count. Minimizing the maximum bond dimension and minimizing NVPS are different optimization problems; this experiment does not claim an optimal parameter allocation. The necessary storage lower bound addresses the possibility that conservative construction alone causes the storage result.

## Quantum-circuit and MPS resource comparison

The generating-description count includes shared active amplitude rotations, independent single-qubit and pairwise phase angles for both spinor components, and one component population. Every phase angle is counted even when generated from a seed; the phase list is not reduced to one seed to obtain an artificial advantage. Gate counts use transpilation into {u,cx}, optimization_level=3, and seed_transpiler=2025, without a hardware coupling map.

**The output endpoints differ.** These gate counts cover only the existing pre-transform spinor-preparation circuits, excluding Gray decoding, Fourier transforms, nonlinear velocity evaluation, measurement, and time evolution. The MPS directly represents three classical velocity arrays. A smaller circuit-description count therefore establishes a compact generating description, not a quantum resource advantage for the same output task; classical computers also store circuit descriptions. Reference-field export itself uses classical simulation and classical decoding.

The data show that the original octal velocity MPS need not reduce actual core storage at the specified errors, and its dimension may approach the algebraic limit. This tests the unverified inference that these velocity fields necessarily have low MPS bond dimension. It does not establish difficult classical simulation of the spinor state, end-to-end quantum advantage across preparation, nonlinear evolution and measurement, or a lack of value in MPS evolution algorithms.

The parity of L sets the central-cut maximum 8^floor(L/2), giving bounds 64, 512, 512, 4096, and 4096 for the five n values. Part of the staircase comes from encoding geometry; five points do not establish a new asymptotic exponent. Also, component_ratio varies with the grid, so this is a scale comparison with manuscript settings, not pure grid convergence for one fixed physical flow.

construction_seconds_sum sums single-run construction times over three components; maximum_worker_peak_rss_bytes is the largest observed RSS of the independent component processes, including input tensors and numerical libraries. Timings come from the actual run, without repeated dedicated-machine benchmarking. classical_compile_seconds and MPS construction times describe different tasks and do not define a quantum speedup.

## Files and reproduction

- ux.npy, uy.npy, and uz.npy under fields/n15, n18, n21, n24, and n27 are complete float64 velocity arrays; complete.json stores settings and checksums.
- mps_uniform/n*/u*/mps_eps_*.npz stores actual MPS cores with axes (left bond, octal physical index, right bond). Boundary ranks are 1.
- mps_uniform/n*/u*/schmidt_spectra.npz stores complete spectra at every scale cut; eps_*.json records error, ranks, storage, and timing.
- results/summary.csv is the aggregate table; components.csv contains 45 component/tolerance records; schmidt_cuts.csv contains cut results; circuit_resources.csv contains generating-circuit references.
- results/tables.tex supplies LaTeX tables; figures/mps_velocity_20261029 contains static PNG and PDF figures.
- original/ contains the public original sources; validation/ contains inputs, outputs, and numerical comparisons from actual original-routine execution.
- run_original_velocity_mps.m independently reads an exported velocity array in MATLAB/Octave and directly calls the unmodified original constructor and reconstructor, for example run_original_velocity_mps(15,'ux',64). This direct route was also executed and validated.
- mps/ and run_mps_equal_budget.py contain early equal-local-budget exploratory records, which are not used in the final tables; final results use mps_uniform/.

The historical run used C:/Users/admin/anaconda3/envs/qiskit/python.exe from the project root, executing data/mps_velocity_20261029/export_velocity.py, run_mps.py, and summarize.py in sequence. Completed results with matching provenance are reused. Original-routine validation runs validate_original.m before validate_original.py.
